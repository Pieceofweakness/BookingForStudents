# ADR-002: Выбор Python-фреймворка для backend

## Контекст

В ADR-001 выбран модульный монолит на Python. Требуется определить
веб-фреймворк для реализации backend-части системы BookingForStudents.

Требования к фреймворку:

- REST API для взаимодействия с frontend (HTML/CSS/JS).
- Работа с PostgreSQL (ORM, миграции).
- Аутентификация и авторизация с ролями (студент, преподаватель, администратор).
- Валидация входных данных (регистрация, создание слотов и т.д.).
- Поддержка фоновой отправки email-уведомлений (асинхронно).
- Развёртывание в Docker.
- Соответствие ADR-001 (модульный монолит с чёткими границами модулей).

Ограничения:

- Команда: 4 человека.
- Срок: один семестр.
- Ни у одного участника нет глубокого промышленного опыта на Python.
- Приоритеты: скорость освоения, простота кода, скорость разработки.

## Рассмотренные альтернативы

### 1. Django + Django REST Framework

«Батарейки в комплекте» — полноценный веб-фреймворк.

Плюсы:
- Встроенный ORM (Django ORM) — быстрая работа с моделями и миграциями.
- Готовая админка (`django.contrib.admin`) — интерфейс администратора
  из коробки, закрывает роль «Администратор» без разработки.
- Встроенная аутентификация с ролями и правами.
- Защита от CSRF, XSS, SQL-инъекций по умолчанию (NFR 3.3).
- Огромное сообщество, много русскоязычных материалов.
- Естественная организация в приложения (`apps/`) — совпадает
  с модулями ADR-001.
- DRF даёт сериализаторы, viewset'ы, permissions для REST API.
- Лёгкая интеграция с Celery для фоновых задач (email-уведомления).

Минусы:
- «Тяжёлый» фреймворк — много магии и неявных соглашений.
- Django ORM требует изучения собственного синтаксиса.
- Async-поддержка слабее, чем у FastAPI.

### 2. FastAPI

Современный асинхронный фреймворк для API.

Плюсы:
- Высокая производительность (ASGI, async/await).
- Автовалидация через Pydantic.
- Автогенерация OpenAPI/Swagger.
- Лёгкий и минималистичный.

Минусы:
- Нет встроенной админки — писать вручную.
- Нет встроенной аутентификации — подключать сторонние библиотеки.
- Нет встроенного ORM — нужно выбирать (SQLAlchemy / Tortoise).
- Требует понимания async/await — сложнее для новичков.
- Меньше готовых решений — больше ручной сборки.

### 3. Flask

Минималистичный синхронный фреймворк.

Плюсы:
- Простой и понятный для новичков.
- Гибкий, легко расширяется.
- Много расширений (Flask-SQLAlchemy, Flask-Login).

Минусы:
- Нет встроенной валидации, ORM, аутентификации — всё через расширения.
- Синхронный по умолчанию.
- Для REST API требует ручной работы (Flask-RESTful).
- Дольше старт проекта из-за «сборки вручную».

## Решение

Выбран Django + Django REST Framework (DRF).

Обоснование:

1. Низкий порог входа. Django имеет самую большую и понятную
   документацию среди Python-фреймворков, множество русскоязычных
   туториалов. Для команды без опыта Python — критично.

2. «Батарейки в комплекте». Django сразу даёт ORM, аутентификацию,
   роли, валидацию, защиту от типовых атак. Это сильно сокращает
   объём кода, который придётся написать.

3. Встроенная админка решает задачу административной панели
   без дополнительной разработки.

4. DRF превращает Django в полноценный REST API-фреймворк:
   сериализаторы, viewset'ы, permissions, пагинация.

5. Соответствие ADR-001. Django-проект
   организуется в приложения (`apps/`), каждое из которых
   соответствует модулю:
   - `apps/auth` — аутентификация;
   - `apps/users` — профили;
   - `apps/slots` — слоты преподавателей;
   - `apps/bookings` — записи и лист ожидания;
   - `apps/notifications` — email-уведомления;
   - `apps/admin_panel` — административные функции.

6. Простая интеграция с Celery для фоновой отправки email —
   что отражено на диаграмме контейнеров (C4 L2).

Технологический стек backend:

- Python 3.11+
- Django 5.x
- Django REST Framework
- PostgreSQL 16 (см. ADR-002 при необходимости)
- Celery + Redis — фоновые задачи (email)
- Gunicorn — WSGI-сервер для продакшна
- Docker + docker-compose

## Последствия

Положительные:

- Быстрый старт — Django генерирует скелет проекта за минуты.
- Готовая админка экономит недели разработки.
- Встроенная аутентификация с ролями закрывает NFR 3.4.
- Django ORM упрощает работу с PostgreSQL (миграции, модели).
- Большое сообщество — легко искать ответы.
- Простая интеграция с Celery для фоновых задач.
- Естественное соответствие модульному монолиту (ADR-001).

Отрицательные:

- Django ORM — отдельный слой абстракции, требующий изучения.
- Производительность ниже, чем у FastAPI — но для NFR (300 пользователей)
  это не критично.
- Меньше гибкости, чем у Flask — но у нас стандартные задачи.
