# Функциональные требования к системе

## 1. Управление слотами мероприятий
1.1 Система должна предоставлять преподавателю возможность создавать слот мероприятия с указанием темы, описания, даты, точного времени, места и максимального кол-ва участников

1.2 Система должна автоматически валидировать данные: 
- проверять корректность даты\времени;
- проверять отсутствие пересечений времени и места мероприятий.

1.3 Система должна автоматически публиковать созданный слот в общем расписании, делая его доступным для просмотра

1.4 Система должна давать возможность преподавателю изменять данные о мероприятии, а также возможность отмены и переноса мероприятия


## 2. Просмотр расписания
2.1 Система должна отображать студенту актуальный список всех доступных мероприятий

2.2 Система должна обновлять данные о мероприятии в реальном времени (включая количество свободных мест)

2.3 Система должна обеспечить централизованное хранение расписания со всей актуальной информацией

2.4 Система должна давать возможность сортировки и фильтрации доступных для записи мероприятий

## 3. Запись на мероприятие
3.1 Система должна дать возможность студенту записаться на мероприятие

3.2 Система должна проверять, не записан ли студент уже на этот слот

3.3 Система должна проверять, есть ли свободные места

3.4 Система должна уведомлять об успешной записи на мероприятие

## 4. Лист ожидания
4.1 Система должна автоматически записывать студента в лист ожидания, при попытке записаться на мероприятия, где все места заняты. После записи в лист ожидания система должна уведомить о текущей позиции в очереди

4.2 Система должна формировать лист ожидания по принципу: первый пришел, первый получил место

4.3 При освобождении места система должна автоматически записывать первого студента из листа ожидания

4.4 Система должна уведомлять студента о записи из листа ожидания

## 5. Автоматический учет
5.1 Система должна автоматически формировать список студентов, записавшихся на каждый слот

5.2 Система должна вести счетчик свободных и занятых мест каждого слота

5.3 Система должна хранить историю записей каждого студента (кто, когда и на какой слот записывался\отменил)

## 6. Уведомления
6.1 Система должна оповещать преподавателя о новых записях на его слоты

6.2 Система должна отправлять студенту подтверждение записи сразу после ее оформления

6.3 Система должна автоматически уведомлять студента о предстоящем мероприятии 

6.4 Система должна уведомлять всех записавшихся на слот об изменении информации (перенос, отмена, изменение места проведения)

## 7. Отмена и изменение записи
7.1 Система должна предоставить возможность студенту отменить свою запись

7.2 При отмене записи система должна автоматически увеличить кол-во свободных мест на 1

7.3 Система должна предоставить возможность преподавателю отменить, перенести или изменить информацию о мероприятии

## 8. Ведение списка
8.1 Система должна автоматически собирать и предоставлять преподавателю актуальный список записавшихся на каждое его мероприятие

8.2 Система должна отображать лист ожидания для каждого его слота

## 9. Аутентификация
9.1 Система должна обеспечить аутентификацию пользователей

9.2 Система должна разграничивать права доступа между преподавателем и студентом

9.3 Система должна поддерживать интеграцию с внешней системой аутентификации и\или использовать локальную аутентификацию
