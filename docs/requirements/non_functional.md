# Нефункциональные требования к системе

## 1. Производительность
1.1 Время отклика API при типовых операциях (просмотр расписания, запись, отмена) **не должно превышать 500 мс** при нагрузке **до 100 одновременных пользователей**

1.2 Время загрузки главной страницы **не должно превышать 2 секунды** на стандартном интернет-соединении

1.3 Операции записи на слот должна выполнятся автономно и завершаться **не более чем за 1 секунду**

1.4 Система должна выдерживать **не менее 300** одновременных пользователей без деградации времени отклика более чем на 30%


## 2. Доступность
2.1 Доступность системы в учебный период **не менее 99% времени**

2.2 Плановые технические работы **не более 2 часов в неделю**

2.3 Время восстановления после сбоя **не более 30 минут**

2.4 Точка восстановления данных **не более 1 часа**. Резервное копирование базы данных **не реже раза в час**

2.5 Система должна корректно работать **в разных браузерах**


## 3. Безопасность
3.1 Все пароли пользователей **должны храниться в виде хешей**

3.2 Весь трафик между клиентом и сервером **должен передаваться по HTTPS**

3.3 Система должна защищать от **основных веб-уязвимостей**

3.4 Разграниченое прав доступа: студент **не может** получиться доступ к функциях преподавателя и **наоборот**

3.5 Сессия пользователя должна автоматически завершаться **после 30 минут** неактивности


## 4. Масштабируемость
4.1 Система должна поддерживать **горизонтальное масштабирование** backend-сервиса

4.2 База данных должна выдерживать рост **до 10000 пользователей** и **100000 записей** без существенной деградации

4.3 Добавление новых типов мероприятий **не должно требовать** изменения архитектуры

4.4 Система должна развертываться **одной командой** через Docker


## 5. Удобство использования
5.1 Интерфейс должен быть **интуитивно понятен**. Новый пользователь может записаться на мероприятие без инструкций

5.2 Действие "Запись на мероприятие" должно выполняться **не более чем за 3 клика** от главной страницы

5.3 Интерфейс должен быть **адаптивным** - корректно отображаться на ПК, планшетах и смартфонах

5.4 Все действия системы должны сопровождаться **понятными сообщениями** (успех\ошибка\предупреждение)

5.5 Интерфейс должен быть на **русском языке**
